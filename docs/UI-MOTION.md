# Плавность интерфейса — 60 FPS

Цель — плавное движение элементов при обычной частоте поступления данных. Статические элементы не
перерисовываются постоянно; сетевые API, частота захвата аудио и измеренные значения не изменены.

## Устройство отрисовки

- `www/animation.js` объединяет покадровые подписки в один `requestAnimationFrame` и ограничивает их
  примерно 60 обновлениями в секунду на дисплеях 120/144 Гц. `draw(timeMs, deltaSeconds)` возвращает
  `true`, пока нужны следующие кадры. `request`, `cancel`, `destroy` управляют подпиской.
- Медиапрогресс рассчитывается по времени воспроизведения, аналоговые часы плавно двигают стрелки,
  секундомер обновляет показания без общего таймера раз в 250 мс. Во время перемотки прогрессом управляет палец.
- Полосы памяти/GPU и круговые индикаторы сохраняют DOM/SVG между обновлениями. Полосы используют
  `transform`; числовые подписи и измерения аудио показывают исходные значения.
- Научные спектры и волны рисуют полученные данные без выдуманных промежуточных точек.
  Спад столбиков и послесвечение стереографика зависят от времени, а не числа кадров.
- Телеметрия объединяется перед визуальным обновлением. События, команды и секундные проверки
  будильников обрабатываются независимо. Скрытые страницы и карточки стека догоняют данные при открытии.
- Фоновое приложение, ночной экран и неактивные карточки останавливают анимацию. После восстановления
  первый кадр получает `deltaSeconds = 0`, без проигрывания пропущенного времени.

## Проверка

Браузерные проверки покрывают 60/120/144 Гц, паузу/восстановление, ночной режим, смену страниц,
Smart Stack, удаление подписок, сохранение DOM индикаторов, перемотку, доступность ползунка,
фоновые таймеры, аудиовиджеты и остановку сетевых запросов в фоне. Проверены 112 сценариев:
111 прошли в общем прогоне, оставшийся тест навигации прошёл повторно после явного задания
начальной страницы в его настройке. Android: `lintDebug assembleDebug` — успешно; итоговый APK установлен на P30T.

Для воспроизведения браузерных проверок из `tools/ui-tests`:

```powershell
npm test -- animation.spec.js controls.spec.js media-scrub.spec.js spectrum.spec.js audio-spectrum.spec.js audio-waveform.spec.js audio-stereo.spec.js audio-loudness.spec.js panel.spec.js timer-deadline.spec.js widgets-clock-refresh.spec.js idle-sync.spec.js widget-requests.spec.js --workers=2
```

Тестовый HTTP-сервер использует очередь 128 подключений: стандартная очередь Python на Windows
иногда отклоняла параллельные загрузки ES-модулей (`ERR_CONNECTION_REFUSED`).

## Замер на Android, 19 ноября 2026

P30T, Android 14, экран 1280 × 800 / 60 Гц, Android WebView Chrome 157. Замер через CDP
именно процесса `net.oxog.phonebox.deskpanel`, по 6 секунд после прогрева страницы. Сохранённая
конфигурация не изменялась; после замера возвращалась исходная страница.

| Сценарий | FPS rAF | Медиана, мс | P95, мс | P99, мс |
|---|---:|---:|---:|---:|
| HTML, часы, два графика, управление и медиаплеер | 59,19 | 16,7 | 16,8 | 33,3 |
| Медиаплеер, часы и прогноз | 60,19 | 16,7 | 16,8 | 16,9 |
| Три графика и память | 59,52 | 16,7 | 17,4 | 21,1 |
| Перелистывание соседних страниц раз в секунду | 55,87 | 16,7 | 18,5 | 49,9 |

Это частота вызовов JavaScript rAF, а не измерение каждого физически показанного кадра GPU.
Во время итогового прогона медиапрогресс обновлялся около 60 раз в секунду на устройстве.
`dumpsys gfxinfo` за весь прогон: 1452 кадра, 47 janky frames (3,24%), GPU P95 — 11 мс.
Эти счётчики Android и интервалы rAF измеряют разные этапы и не равны друг другу.
Полная одновременная нагрузка всех аудиоанализаторов на устройстве этим замером не покрыта.
Стабильные 60 FPS во всех сценариях не заявляются: на сложных страницах и при перелистывании остаются пропуски.

Повторный замер: сначала проверить PID через `adb shell pidof net.oxog.phonebox.deskpanel`,
затем пробросить только его `webview_devtools_remote_<PID>` на локальный порт:

```powershell
adb forward tcp:9223 localabstract:webview_devtools_remote_<PID>
node tools/ui-tests/android-motion.js http://127.0.0.1:9223 .temp_files/android-motion.json
adb forward --remove tcp:9223
```

Скрипт дополнительно проверяет Android-Package отладочного сервера и возвращает исходную страницу.
Камеры и сторонний контент в iframe сохраняют собственную частоту обновления.
